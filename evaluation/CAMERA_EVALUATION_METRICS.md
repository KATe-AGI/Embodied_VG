# 相机系插头配准评测指标提案

当前完整评测集为 `test_data/plug_camera_eval_20261106`：原先接受的 156 条，加上
2026-11-06 用户接受的重新配准 20 条，共 176 条。下述阈值是讨论提案，尚未锁定。

## 评价对象与对称性

所有位置在 RGB 相机系下，以米存储、毫米报告。模型抓取原点为 `[0,0,0]`，
尾中心为 `[-0.0778,0,0]`，头中心为 `[0.09,0,0]`，尾到头长度 167.8 mm。
本任务忽略绕长轴的 roll，保留头尾身份：转动 roll 不扣分，头尾反转必须扣分。
实际评价对象是三维位置和有向长轴，即任务相关的五个自由度。

本集真值来自用户接受的算法配准，并非独立测量。相对于参考的毫米级差值用于
比较算法版本，不能单独证明绝对物理定位精度。冻结真值，避免随新算法输出更新。

## 建议主指标

令 `p` 为抓取原点，`a` 为归一化尾到头方向，下标 `gt` 和 `pred` 表示真值和预测。

1. 抓取原点误差：`e_p = 1000 * norm(p_pred - p_gt)`，单位 mm。
2. 有向长轴角误差：`e_a = degrees(acos(clip(dot(a_pred,a_gt),-1,1)))`。
   不对点积取绝对值，角度范围为 0–180°。
3. 联合成功率：`mean(valid_prediction AND e_p <= tau_p AND e_a <= tau_a)`。
   分母固定为全部 176 条，缺失、无效、程序失败、拒绝输出均算失败。

建议初始报告阈值组合 `(2 mm,2°)`、`(5 mm,5°)`、`(10 mm,10°)`，
其中 `5 mm / 5°` 暂作为主成功率。最终阈值应根据夹爪和插头的几何余量确定。
报告成功率表或阈值曲线，避免只选对某算法有利的单个阈值。

## 辅助定位指标

- 轴向偏移：`e_parallel = 1000 * abs(dot(p_pred-p_gt,a_gt))`。
- 横向偏移：`e_perp = 1000 * norm((p_pred-p_gt)-dot(p_pred-p_gt,a_gt)*a_gt)`。
- 头中心和尾中心分别计算欧氏误差，用于放大并诊断长轴倾斜和头尾混淆。
- 单帧三语义点 RMSE：`sqrt((e_grasp²+e_tail²+e_head²)/3)`。
  总体三点 RMSE 为所有有效帧各语义点平方误差的均值开方；应同时注明有效帧覆盖率。
  它可以辅助排序，但同时混合位置误差和长轴误差，不能替代二者的独立报告。
- 有向轴误差 `>90°` 的比例作为方向严重错误率。该比例不等同于精确的头尾交换检测，
  具体是否反转应结合接近 180° 的误差和图像复核。

位置指标报告 median、P90、P95、RMSE；角度指标报告 median、P90、P95。
同时保留逐帧指标，列出误差最大的样本。不能让只在容易样本上输出的算法通过
舍弃失败帧获得更好的主成功率。

## 重复性和速度

针对原来跨机器不稳定的问题，建议在至少两台机器上，对同一批输入、同一配置、
同一代码和依赖记录分别运行 10 次。记录不同 seed，并额外检查同一 seed 跨机器。
既报告每次相对真值的误差，也报告同帧重复输出之间的位置/有向轴偏差和成功率波动。
重复性与准确性要分开看：稳定地输出错误姿态仍然是错误。

记录单帧预热后总推理耗时 median / P95，包含分割、点云提取和配准；
模型加载与文件保存另记。比较时使用相同硬件、batch size、分辨率和线程数，
GPU 计时需同步。可视化写盘耗时不计入算法本体耗时。

## 汇总和开发协议

- 同时报告全部 176 条、原参考 156 条、重新配准 20 条，以防总体平均掩盖困难样本。
  两个子集只代表来源和历史难度，不代表不同的真值接受等级。
- 按拍摄日期/采集组和相机内参分别报告；必要时报告组间宏平均。
- 相邻帧可能高度相关，应按采集序列/场景划分开发集与留出集。仅按帧随机划分或
  leave-one-frame-out 无法保证与开发数据独立。本版本保留分组但尚不指定数据划分。
- 相机内参逐帧取评测集指定配置。早期相机身份存在历史不确定性，不应静默换成
  当前相机内参。若未来重建真值，须发布新版本并保留这一冻结版本。
- 轮廓 IoU、点到 CAD 距离、`depth_cost` 属于拟合诊断；遮挡或对称性可能使错误姿态
  获得良好分数，不作为相对真值准确率的主指标，也不用它们筛掉评测失败帧。
- 完整旋转矩阵角误差会惩罚当前任务忽略的 roll；通用 ADD-S 的最近点匹配又可能
  掩盖近似头尾对称，不建议将它们用作当前任务的主排名指标。

`evaluation/evaluate_camera_pose.py` 提供单帧语义点、轴向/横向及有向轴误差。
新入口 `evaluation/evaluate_camera_benchmark.py` 读取冻结 manifest，按上述三档阈值报告
联合成功率、连续误差、时间及分组统计；缺失、失败、退化轴均计入失败。

`tools/run_camera_baseline.py` 直接调用 `infer_6d_single.run`，保留原算法和参数，
仅复用驻留的分割/CAD 模型并在分阶段计时边界同步 GPU。默认预热 3 帧，
随后执行 10 轮，seed=7..16。第一轮定义本次准确率基线；所有预热后轮次汇总耗时，
并另报重复性。单轮完整调用耗时也记录，包括输入读取和预测 JSON 保存，不包括模型加载。
首帧初始化和模型加载独立留档；不启用可视化写盘。运行会保存代码快照、模型和数据哈希。

```bash
python tools/run_camera_baseline.py \
  --dataset test_data/plug_camera_eval_20261106 \
  --output-dir output/camera_baseline_symmetric_20261106 \
  --device 0 --warmup-frames 3 --repeats 10 --seed 7
```

评测集内 `METRICS_PROPOSAL.md` 是冻结创建时的提案副本；本文件说明后续已实现的协议。
