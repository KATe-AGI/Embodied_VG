点云预处理 edge_clean 实现与验证报告

结论
已实现并验证一个可运行的可选版本。对孤立飞点、小型不连续深度碎片及表面抖动有效，但尚未实现“只剩真实插头表面”的完整清理。可视化仍见与主体连续相连的拖尾；不能证明真实端点精度已提高。默认仍为 none。

顺序与参数
1. 使用原始分割掩码，保留 0.1–1.0 m 的有限深度。edge_clean 替代固定 5 px 腐蚀和全局 Z-MAD；其他模式保持原行为。
2. 5×5 像素邻域深度支持：至少 3 个相近深度邻居，且占有效邻居至少 40%。深度差阈值为 0.002 + 0.002*(z/0.7)^2 米。这是待标定的工程阈值，不是已验证的相机噪声模型。
3. 在上一步结果上按 8 邻接与深度连续性建立连通片，删除小于 max(64, ceil(0.005*N)) 点的碎片；极小输入有对应保护规则。保留多个足够大的独立表面，不只保留最大块。小而真实的遮挡碎片仍可能误删。
4. 反投影，执行半径离群点过滤。半径为 max(2 mm, 3*z/min(fx,fy))，至少 3 个邻居，不计自身。通过 SciPy cKDTree 实现标准 ROR 判据。
5. 只在保留像素上做一次 3×3 深度双边滤波，空间 sigma=1 px，深度 sigma=1.5 mm，禁止跨越深度差门槛。单点深度变化上限 1 mm；三维位移略大于深度位移。
6. 导出完整清洁点云、以米为单位的清洁深度及有效像素掩码。配准输入另做 4 mm 体素质心采样，并保留原 200 点检查。
不填洞、不补面、不用 CAD/伪真值调整点，也不强制可动圆环回到固定位置。
本实现是 NumPy/SciPy 的组织化深度过滤与双边实现，没有调用 RealSense SDK 原生空间滤波器。

验证范围
176 帧冻结数据，使用既有分割缓存完成点云对照；正式入口另外重新执行分割并完成 176 帧配准。

全部真实数据均参与过诊断，因此没有独立盲测集。
93 项测试通过；包括飞点/条带、小型密集碎片、相隔 1 cm 的真实深度层、孔洞、倾斜表面、平滑位移、极小输入与完整入口。
旧默认 none：176 帧与修改前点云逐点完全一致。
单帧正式入口 --save-ply 已验证生成完整点云、配准点云、深度和掩码。

可视化判断与局限
首帧的远离主体小碎片明显减少，但仍有连续附着的长拖尾。小连通片过滤不能分辨足够大且自洽的错误深度表面。
最低核心保留率样本为 20261026_111022_2332035_001_plug；可视化显示删去了较多稀疏结构，仅凭当前数据无法断定全部是噪声。
因此目前适合做可选清理与进一步标注审查，不适合宣称是完全验证的生产默认方案。
下一项最有价值的证据，是对残留拖尾和被删除区域做少量人工“可靠表面/明显噪声/不确定”标注，并检查原始深度与 D2RGB 对齐；不应继续仅靠提高删除阈值使图变干净。

使用方法
在项目目录和 embodiedvg 环境下，在原单帧命令中添加：
  --point-filter edge_clean --save-ply
完整输出：*_clean_full.ply
配准用降采样输出：*_visible_points.ply
清洁深度与掩码：*_clean_depth_m.npy、*_clean_valid_mask.npy
回到原处理：--point-filter none

全量清理审查：
python tools/audit_edge_clean.py --output-dir output/<新的审查目录>
此脚本针对当前冻结的 176 帧和已有分割缓存，输出指标及选定样本的对比图。
正式端到端验证：
python tools/run_camera_baseline.py --dataset test_data/plug_camera_eval_20261106 --output-dir output/<新的运行目录> --point-filter edge_clean --repeats 1 --warmup-frames 3 --device 0
